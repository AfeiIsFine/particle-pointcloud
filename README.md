# 图片转粒子点云效果 · Image → Particle Point Cloud

**中文** | [English](README.en.md)

把一张图片变成**可交互的 3D 粒子点云**。纯前端、单文件、零依赖上传 ——
图片全程在你自己的浏览器里处理，不会发往任何服务器。

**在线试用**：<https://afeiisfine.mindpion.workers.dev/>

![演示：彩色抽象 → 粒子聚集成树](screenshots/demo.gif)

## 这是什么

一个用 three.js 写的网页工具。拖一张图进去，它会按像素亮度把画面采样成几万个 3D 粒子，
并根据"图里面积最大的颜色"自动判断背景明暗、配好一整套参数，让你打开就能看到成品，
而不是对着一个空场景调滑块。

两种粒子形态，各自解决一个具体问题：

| 形态 | 是什么 | 适合 |
|---|---|---|
| **柔和光点**（默认） | 圆点带柔边，用"深度预通道"建立前后遮挡：近处粒子的实心核心挡住后面的粒子，边缘依然柔和 | 氛围、抽象、光感 |
| **实心球体** | 每颗粒子渲染成受光的实心小球，逐像素球面深度 + 烘焙接触阴影，经 ACES 电影级色调映射 | 实物、雕塑、有体积感的画面 |

下面两张都是用仓库内默认素材 `testpic/black_4.jpg` 渲染的，粒子数同为 5 万、同一机位，
只有形态和尺寸不同（柔光点 0.5 / 实心球 1.0）—— 两者的最优尺寸本来就不同：
实心球是受光实体，而光点会叠加增亮，用同样大小会糊成一团：

| 柔和光点 | 实心球体 |
|---|---|
| ![柔和光点](screenshots/form-soft-dots.png) | ![实心球体](screenshots/form-solid-spheres.png) |

## 怎么用

### 方式一：直接用（不需要装任何东西）

下载 `index.html`，双击用浏览器打开（推荐 Chrome / Edge / Safari 最新版）。
打开即自动载入一张示例图，可以直接开始调。

### 方式二：本地起个服务（开发用）

```bash
python3 -m http.server 8123
# 浏览器打开 http://127.0.0.1:8123/index.html
```

> 双击（`file://`）时读不到同目录的 `testpic/black_4.jpg`，页面会是空的 —— 这是浏览器的
> 同源策略，不是 bug。本地开发请用方式二，或打开时在网址末尾加 `?test` 加载内置示例图。

### 操作

- **左键拖动** = 旋转 · **滚轮** = 缩放 · **中键 / 右键拖动** = 平移
- 每个滑杆左侧的小 `↺` 可以把该参数一键还原成默认值
- 面板分左右两栏、共 7 组，点组标题折叠展开；点面板右上角 `—` 收起整个面板（方便录屏）

### 网址参数（调试 / 固定状态用）

| 参数 | 作用 |
|---|---|
| `?test` | 加载内置测试图，跳过默认素材 |
| `?blank` | 空场景启动（不加载任何素材） |
| `?stats=1` | 控制台输出采样统计 |
| `?dist=` / `?lumMin=` / `?lumMax=` / `?solid=` | 固定对应参数，屏蔽换图时的自动判定 |
| `?bgauto=0` | 一次性关掉整块自动配色/配参逻辑 |

## 功能

- **素材**：拖入图片 / 视频 / GIF / 整个文件夹；GIF 与视频会实时驱动粒子颜色与深度
- **换图自动配参**：背景色取"面积最大的颜色"；暗背景 → 亮度下限 30 / 上限 255 / 柔和光点；
  亮背景 → 亮度下限 0 / 上限 240 / 实心球体
- **粒子分布**：数量（最高 300,000）、亮度上下限、分布偏向、深度强度、噪声扰动
- **粒子外观**：大小、透明度、明度、饱和度、粒子形态、球体光泽、辉光、背景颜色（可渐变）
- **粒子动态**：沿亮度轨迹逐级流动往返，可设起点 / 终点 / 速度 / 相位散布
- **镜头视角**：自动旋转、视图回中心
- **渲染导出**：单帧 PNG / 逐帧序列（离线渲染，不卡顿；帧序列导入剪辑软件即可合成视频）
- **中英双语**界面切换

## 实测性能

数据来源：headless Chrome + 系统 Chrome（真实 GPU，ANGLE Metal / Apple M1 Max），
1440×900 画布，20,000 个粒子。

| 场景 | 帧率 | p95 帧时间 | JS 堆 |
|---|---|---|---|
| 默认 20k · 柔光点 · 无辉光 | 60.0 fps | 18.0 ms | 8.1 MB |
| 100k | 60.0 fps | 18.2 ms | 12.0 MB |
| 300k（滑块上限） | 60.0 fps | 18.3 ms | 21.1 MB |
| 实心球体 20k | 60.0 fps | 17.3 ms | 8.1 MB |
| 辉光 1.0 + 100k | 60.0 fps | 18.2 ms | 12.1 MB |

流动动画（20k 粒子 × 12 关键帧轨迹，Catmull-Rom 每帧 CPU 插值）：**0.6 – 2.8 ms/帧**。

## 几个有意思的实现细节

这个项目里踩过的坑比功能本身更值得看，都是一行注释解释"为什么"而不是复述"是什么"：

**为什么实心球体必须不透明。** 半透明像素写进深度缓冲会把后面的粒子剔掉，只剩它自己以极低
alpha 与黑背景混合 → 每颗粒子套一圈暗环。实测"被粒子包围的孤立黑点"：柔和光点 0 个、
旧的硬边遮挡方案 **559 个**。所以实心球模式下轮廓用硬切（`rho2 > 1` 直接 discard），
参与深度写入的像素 alpha 恒为 1，黑边从结构上不可能出现；"透明度"这个滑块改为压暗 RGB，
而不是降低 alpha。

**粒子大小不能是常数。** 最初的 `gl_PointSize = uSize * rand * (160.0 / -mv.z)` 里 160.0
写死了、不含视口高度，后果是分辨率越高粒子反而越小（900×600 → 1800×1200，覆盖率比 0.68）。
现在乘上 `uResScale = 绘制缓冲高度 / 1800`，粒子的世界尺寸恒定 —— 预览与导出所见即所得，
Retina 与非 Retina 观感一致。

**导出必须与预览完全一致。** `EffectComposer` 的像素比是构造时锁定的，导出时只改 renderer
不改 composer，粒子会画在 2× 缓冲上再被降采样 → 又小又灰（实测覆盖率比 0.492、亮度 133.9 → 107.5）。
修法是两者一起改、导出后一起还原，复测覆盖率比 **0.999**。

**颜色管线不能重复编码。** 最小复现页证明 `OutputPass` 会把着色器输出再编码一次 sRGB：
直出画布读回 128、走 composer 读回 188。所以图片像素必须先 `srgbToLinear()` 解码再送进着色器，
否则 double gamma 会让整幅画面发灰发白。

**流动动画不能从端点起步。** 默认动态范围 −0.9 ~ +0.9、用户当前停在 +0.7，一点"开始流动"
就猛跳到暗端，观感是"一按就变暗"。修法是记下最接近当前分布的那一级作为起始相位。

### 示例素材

`testpic/` 里 9 张都是可以直接拖进去试的图，按背景明暗分两组
（换图时的自动判定会因此给出不同的默认参数）：

| 文件 | 背景 | 自动判定的默认参数 |
|---|---|---|
| `black_0.jpg` … `black_5.jpg` | 暗 | 亮度下限 30 / 上限 255、分布偏向 +0.7、**柔和光点** |
| `white_0.jpg` … `white_2.jpg` | 亮 | 亮度下限 0 / 上限 240、分布偏向 0、**实心球体** |

其中 **`black_4.jpg` 是页面打开时自动加载的默认素材**（文件名写死在代码里），
其余 8 张只用于替换测试。

## 开发与测试

`.test/` 下保留了开发期的回归脚本与说明（`node_modules/` 与调试截图不在版本库内）：

```bash
node .test/test_sampling.mjs        # 算法级：采样分布 / 亮度过滤 / 配对质量 / 波形
cd .test/pup && npm i               # 浏览器级测试首次需装依赖
node .test/pup/review_checks.js     # 回归守卫（约 28 秒、5 项断言）
```

回归守卫的用法是「发现一个 bug → 先补一条断言 → 再修代码」，避免同一个坑踩第二次。
`.test/README.md` 里记录了每个脚本查什么，以及若干设计约束的实测数据
（例如"实心球体为什么必须不透明"的对照实验）。

三个这次做演示素材时写的工具，也放在这里可复用：

- `.test/pup/form_shots.js` —— 用默认素材出两种形态的对照图
- `.test/pup/video_probe.swift` —— 纯 AVFoundation 抽帧/读元数据，**不需要 ffmpeg**
  （`swift video_probe.swift <视频> <输出目录> sample` 均匀抽 12 帧看内容；
  加 `frames <起> <止> <fps> <宽>` 抽连续帧，可用来做 GIF）
- `.test/pup/video_encode.swift` —— 纯 AVFoundation 剪辑+转码，**不需要 ffmpeg**
  （按秒指定若干片段拼成一支高光片，再导出 720p H.264；上面 README 里的演示图与
  演示片就是这么做的）

### 打包成单文件

`index.html` 依赖同目录的 `libs/`，直接双击会因同源策略读不到。要做一个**能双击直接用**
的单文件版本：

```bash
python3 build_share.py            # → dist/index.html     内嵌 three.js 与示例图
python3 build_share.py --web      # → dist-web/index.html 不内嵌示例图，体积更小（线上部署用）
```

需要 `npx`（即本机有 Node.js），脚本会调用 esbuild 打包成 IIFE 单文件。
线上版首次打开传输量约 156 KB（Brotli 后），比不打包的版本快得多。
