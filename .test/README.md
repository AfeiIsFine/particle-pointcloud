## 实心球体为什么必须不透明（重要设计约束）

黑边（halo）的成因是**半透明像素写进了深度缓冲**：粒子外圈的半透明像素把后面的粒子剔掉了，
只剩它自己以极低 alpha 与黑背景混合 → 每颗粒子套一圈暗环。
实测"被粒子包围的孤立黑点"：柔和光点 0 个、旧的硬边遮挡方案 **559 个**、实心球体 **5 个**。

所以实心球模式下：
- 轮廓用硬切（`rho2 > 1` 直接 discard），**参与深度写入的像素 alpha 恒为 1**，黑边从结构上不可能出现；
- 透明度 uAlpha 改为**压暗 RGB** 而不是降低 alpha（背景是纯黑，观感等同变透），
  这样"调透明度"不会重新引入黑边，遮挡关系也完全不受影响；
- 用 `gl_FragDepth` 写**逐像素球面深度**，球与球相交时是真的穿入，而不是整片圆盘互相压盖。

代价：轮廓没有抗锯齿（球体边缘本来就是背光暗部，肉眼几乎看不出）。

## 粒子的"世界尺寸"与分辨率（已修复的 bug）

原实现 `gl_PointSize = uSize * rand * (160.0 / -mv.z)` 里的 160.0 是写死的常数、不含视口高度，
后果是**分辨率越高、粒子在画面里反而越小**（实测 900x600 → 1800x1200，覆盖率比 0.68）。
现在乘上 `uResScale = 绘制缓冲高度 / AO_REF_HEIGHT(1800)`，粒子的世界尺寸恒定：
- 预览与导出所见即所得；4K 导出 = 像素数等比增加 = 真的更细腻
- Retina 与非 Retina 屏幕观感一致（原先在 Retina 上粒子只有一半大小）
- 改「粒子大小」滑块即可整体调大调小

## 接触阴影（AO）

`bakeAO()` 用均匀网格 + 计数排序（O(n)）统计每颗粒子的邻近密度，
按 `(1-d/R)²` 累加（该权重在球内平均值为 0.1，物理含义明确），
再以 occ 的 85 分位为参考归一化 → 表层粒子接近 1、埋在内部的压暗到 0.38。
用途：让一堆球读成"一坨实体"而不是一堆各自独立打光的浮球。

- 只在**实心球体**模式下烘焙（柔和光点的着色器不读 aAO，默认模式不为它付代价）；
  从柔和点切到球体时在 `rebuildMaterials()` 里按需补烘。
- 烘焙耗时：20k = 88ms / 80k = 286ms / 300k = 1161ms（仅在重建粒子时发生一次）。
- 教训：`aoForPositions` 不能放进 `sampleFromScan()` —— 流动动画的 19 个关键帧都会调它，
  会把 AO 白烘 19 遍（轨迹构建从 2.2s 涨到 6s+）。

## 导出必须与预览一致（已修的 bug）

`EffectComposer` 的像素比是**构造时**从 renderer 锁定的。导出时只调 `renderer.setPixelRatio(1)`
而不同步 composer，composer 仍按屏幕 dpr（Retina = 2）渲染：粒子尺寸按 canvas 高度算、却画在
2× 的缓冲上 → **相对尺寸直接减半**，最后再被 2× 降采样 → 又小又灰。
实测覆盖率比 0.492（正好一半）、平均亮度 133.9 → 107.5。
修法：`composer.setPixelRatio()` 与 renderer 一起改、导出结束后一起还原。
同宽高比下复测：覆盖率比 **0.999**、亮度 134.8 vs 133.6 —— 完全一致。

（宽高比不同时覆盖率仍会差，那是取景差异：透视相机的垂直 FOV 固定，更宽的画幅会看到更多横向内容。）

## 流动动画的"一按就变暗"

根因不是颜色（颜色已固定不随分布漂移），而是**动画从动态范围的端点起步**：
默认范围 -0.9~+0.9、用户当前在 +0.7，一点击就猛跳到暗端。
修法：`beginAnimLoop()` 记下"最接近当前分布偏向"的那一级作为起始相位 `phase0`，
播放时把它加到时间轴上（交叉淡化仍用原始时间，保证淡化仍是 0.4s）。
实测覆盖率 13.7%→13.05%、亮度 77.4→71.5（修前是 −22% / −15%）。

## 滑杆的重置按钮

`bindRange()` 会给每个滑杆在标签旁挂一个 `↺`（`.rv`）：平时 opacity 0.3、悬停 1.0，
**已处于默认值时降到 0.08 且不可点**，做到"和谐不突出"。

## 重算等待提示（#busy）

`buildPoints`（采样 + 烘焙 AO）是同步的、会阻塞主线程，所以先把提示画出来、让浏览器走完
两帧再开始重算。两个必须注意的点：

- **不能用计数器**："连续拖动 → 防抖"会让 `show()` 被调用 N 次而只有 1 次 `hide()`，
  计数只加不减，提示永久卡住（用户实际遇到的 bug）。改用**令牌**：只有最新一次能收起提示。
- **再加一道看门狗**（15 秒）兜底，任何路径漏收起也不会永久停留。

`?dist=` 显式给定时会置 `window.__PC_DIST_FIXED`，用于避免上传图片后的自动值覆盖调试参数。

## 上传图片后的自动判断

1. 背景色 = 图片中面积最大的颜色（`dominantColor()`，RGB 量化成 32³ 直方图取最大桶再求均值）
2. 分布偏向 = 按该背景色的明暗：亮度 > `AUTO_DIST_THRESHOLD`(140) → 0（亮背景，往亮部聚集
   只会把主体淹没）；否则 → 0.7（暗背景，亮部通常就是主体）

两个自动值都只在**换图时**写入，之后手动拖滑块即可覆盖。

## 亮度带通（下限 / 上限）

`prepareScan()` 里用 `lumLo / lumHi` 过滤。要点：
- **默认下限 0**：旧版默认 0.5，`L < 0.5` 会把所有纯黑像素（L=0）删掉——这就是"黑色粒子看不见"的原因。
- 上下限用 `Number.isFinite` 兜底：写成 `Math.min(params.lumMin, params.lumMax)` 时若某个值是 undefined，
  结果是 NaN，而 `L < NaN` 恒为 false → **整个过滤会静默失效**（踩过一次）。
- 上下限写反不报错，自动取小值为下限。

## 球体不再写 gl_FragDepth（穿模修复）

原先写"逐像素球面深度"让球与球真实相交，粒子一大就出现一圈圈圆形缺口/火山口（像穿模）。
实测 `bulge=0`（整颗取中心深度）完全没有该现象，且球体轮廓完整 —— 这也是点云的标准做法。
现在整段 gl_FragDepth 机制已移除，顺带恢复了 GPU 的 early-Z。
当时用于对照的 `?bulge=` 参数已一并删除。

## 柔和光点的前后遮挡（深度预通道）

柔和光点的黑边成因是"半透明像素写深度"：整片都写深度时，外圈半透明像素会把后面的粒子
剔掉、只剩自己与黑背景混合 → 每颗粒子一圈黑环（早期版本实测 559 个孤立黑点）。
所以不能简单地打开 depthWrite，而是拆成**两遍**：

1. `fragCore`（`colorWrite:false` + `depthWrite:true`，进不透明队列所以先渲染）
   只画"自身不透明度 ≥ uCoreT"的核心 → 建立前后关系，**不出颜色**
2. `fragNormal` 照常画完整柔边，只做深度测试不再写深度

于是中心被近处核心挡住（不再透出后面的粒子），边缘仍是柔的。
核心大小随粒子明暗自适应：越暗的粒子核心越小，越透明的粒子不参与遮挡（看得穿的不该挡别人）。

**关键补充：核心区域必须同时输出 alpha = 1（`a = mix(a, 1.0, step(uCoreT, a) * uSolid)`）。**
只让核心写深度还不够——核心边界处"后面已被剔除、自己又只有 ~35% 不透明"，
那些像素只能与黑背景混合，于是每颗粒子套一圈**暗环**（实测放大后非常明显）。
让"写深度的像素同时输出 alpha = 1"，暗环就从结构上不可能出现。
`coret` 默认 0.5：数值越大实心核心越小、柔边越宽。

- 两个材质**共用同一个 uniforms 对象**，参数自动同步，无需逐帧拷贝。
- 实心球体自己就写深度，预通道层在该模式下隐藏。
- 代价：软件渲染实测帧时间 90.6ms → 120.4ms（+33%）；真实 GPU 上预通道是纯深度写入，开销应明显更小。
- `?nocore=1` 可关掉预通道做对照；`?coret=` 调核心阈值（默认 0.35）。

## 3. 审核回归守卫（2026-10-11 代码审核发现，一条命令 5 项断言）

```bash
cd pup && node review_checks.js      # 需先起本地服务；约 28 秒；全过退出码 0
```

只要**一条命令 + 一个退出码**，断言的都是"用户能看见的症状"，不是"没报错"：

| 断言 | 修复前的实测坏数值（2026-10-11 / M1 Max） |
|---|---|
| 导出点「取消」不显示错误提示 | `#errbar` = "! 模块加载失败：The user aborted a request." |
| 实心球体 100k 单帧阻塞 < 1500 ms | **4372 ms** 同步冻结（20k=618 / 50k=2606 / 200k=10303 / 300k=17812） |
| 收起面板后键盘可达 + 焦点不进不可见控件 | `#toggleBtn` 是 `DIV` / `tabIndex=-1`；30 次 Tab 有 13 个不可见控件拿到焦点 |
| `prefers-reduced-motion` 下不自动播放流动 | 仍然自动开播（按钮 = "停止流动"） |
| `dist` 分享版与开发版同步 | dist 缺 `recStop` / `recProgress` / `recStopping` 词条 |

**踩过的坑（都实际踩了，别再踩）：**
- **测导出不能带 `?stats=1`** —— 那会进导出测试模式、跳过 `showDirectoryPicker`，
  "取消导出"这个 bug 会**假性消失**（我第一轮就是这么测错的）。
- **别用 `?settle=1` 量帧率** —— 上面已写明它 10 帧后停掉 `animate()`；此时量到的是空 rAF 的 60Hz，
  不是真实帧率，所有场景都会"看起来 60fps"。
- **跨页面加载的截帧不能直接比像素** —— `Math.random()` 让粒子抖动 / 随机尺寸 / 颜色微扰每次都不同，
  且 `uFloatAmp` 的漂浮动画还在动。要比就先给 RNG 播种（见 `review_checks.js` 的 `seedRandom`）
  并把 `#floatAmp` 设为 0，否则差异全部来自噪声（我为此白跑了两轮）。
- 只调小 AO 搜索半径（`?aorad=3`）**不会**让第 2 条变绿（4.4s → 1.4s，仍是可感知的冻结）；
  要变绿必须把 AO 烘焙分片或移出主线程。
